Automação e Segurança na Cloud

A passagem de “construir e orquestrar” para “automatizar e proteger” - com cada sigla explicada, exemplos simples e a conexão com o ToggleMaster.

Guia de estudo 4 pilares + glossário de siglas + exemplo no Tech Challenge Atualizado em 2026-07-18

Qual é a mudança desta fase?

Na fase anterior, aprendemos a colocar uma aplicação no ar usando containers e Kubernetes. Agora vamos criar uma esteira automática que prepara, testa e entrega o software, enquanto verificações de segurança protegem o caminho.

Por que combina com o nosso projeto

O ToggleMaster possui vários microsserviços. Fazer testes, criar imagens e atualizar cada serviço manualmente seria lento e sujeito a erro. Nesta fase, a infraestrutura vira código e cada mudança passa por uma linha de montagem com controle de qualidade.

Glossário - o significado das siglas

Os principais termos apresentados pelo módulo, primeiro em linguagem simples.

CloudnuvemComputadores e serviços alugados pela internet, como os recursos da AWS.
CIContinuous IntegrationIntegração contínua: testar cada mudança de código automaticamente.
CDContinuous Delivery/DeploymentEntrega ou implantação contínua: preparar e publicar novas versões com automação.
PipelineA “esteira” que executa tarefas como teste, análise, build e deploy.
GitHub ActionsFerramenta do GitHub que executa pipelines descritos em arquivos YAML.
YAMLFormato de texto usado para escrever configurações e pipelines.
StageetapaUma fase do pipeline, como testar, analisar segurança ou publicar.
ParalelismoExecutar tarefas independentes ao mesmo tempo para terminar mais rápido.
ConditioncondiçãoRegra que decide se uma etapa deve ou não ser executada.
EnvironmentambienteSeparação entre desenvolvimento, homologação e produção.
SecretsegredoSenha, token ou chave armazenada de forma protegida, fora do código.
ObservabilidadeLogs, métricas e alertas usados para entender o que aconteceu no sistema ou pipeline.
IaCInfrastructure as CodeInfraestrutura como código: criar recursos de nuvem usando arquivos versionados.
TerraformFerramenta que lê arquivos de IaC e cria ou atualiza recursos.
OpenTofuAlternativa aberta ao Terraform, com funcionamento semelhante.
TerragruntFerramenta que ajuda a organizar e reaproveitar configurações Terraform maiores.
ProviderConector que permite ao Terraform conversar com AWS, Kubernetes e outras plataformas.
DevSecOpsDesenvolvimento, operações e segurança trabalhando juntos durante toda a entrega.
Shift LeftTrazer a segurança para o começo do desenvolvimento, antes da produção.
SASTStatic Application Security TestingProcura falhas no código sem precisar executar a aplicação.
DASTDynamic Application Security TestingTesta a aplicação funcionando, simulando requisições e ataques.
OWASPOpen Worldwide Application Security ProjectOrganização que reúne riscos e boas práticas de segurança para aplicações.
MITREOrganização que mantém referências sobre técnicas usadas por atacantes e formas de defesa.
DDoSDistributed Denial of ServiceAtaque que envia tráfego em excesso para tentar derrubar um serviço.
LGPDLei Geral de Proteção de DadosLei brasileira sobre coleta, uso, armazenamento e proteção de dados pessoais.
SIEMSecurity Information and Event ManagementCentraliza logs de segurança e ajuda a identificar atividades suspeitas.
Zero Trustconfiança zeroNinguém recebe confiança automática; cada acesso deve ser verificado.
IAMIdentity and Access ManagementControla quem pode acessar cada recurso e o que pode fazer.
MFAMulti-Factor AuthenticationExige uma confirmação adicional além da senha.
CSPMCloud Security Posture ManagementProcura configurações inseguras e problemas de conformidade na nuvem.
CWPPCloud Workload Protection PlatformProtege máquinas, containers e outras cargas executadas na nuvem.
CASBCloud Access Security BrokerAjuda a controlar o acesso e o uso de serviços de nuvem externos.

Os 4 pilares, um a um

Cada ficha segue o padrão do material de estudo: explicação simples, finalidade, caso de uso e aplicação no ToggleMaster.

01

CI/CD - automatizar o ciclo de vida do software

Usaremos no projeto
Em miúdos
É uma linha de montagem. Quando alguém altera o código, máquinas virtuais executam sozinhas os testes, as verificações e a preparação da nova versão.
Termos principais
GitHub Actions, pipeline, paralelismo, multistage, conditions, environments, secrets, logs e alertas.
Para que serve
Entregar mudanças mais rápido, sempre do mesmo jeito e com menos erros manuais.
Caso de uso
Uma alteração no serviço de autenticação inicia testes e análise de segurança. A versão só pode avançar se tudo passar.
No ToggleMaster
Cada microsserviço terá uma esteira capaz de validar o código, construir a imagem do container e preparar a nova versão para o Kubernetes.
02

IaC - transformar a infraestrutura em código

Usaremos no projeto
Em miúdos
Em vez de criar servidores e redes clicando no painel da AWS, escrevemos uma “planta da construção”. O Terraform lê essa planta e monta a infraestrutura.
Termos principais
Terraform, OpenTofu, Terragrunt, módulos, variáveis, loops, condicionais e providers.
Para que serve
Tornar a infraestrutura versionável, auditável, repetível e mais fácil de revisar.
Caso de uso
Criar o ambiente de testes e o ambiente de produção a partir dos mesmos módulos, mudando apenas os valores necessários.
No ToggleMaster
A rede, o cluster Kubernetes, os bancos e os demais serviços AWS serão descritos em arquivos Terraform, sem depender de configuração manual no console.
03

DevSecOps - segurança dentro da entrega

Usaremos no projeto
Em miúdos
O controle de qualidade não fica apenas no final da fábrica. Ele acompanha cada etapa e impede que um produto perigoso chegue ao cliente.
Termos principais
Shift Left, SAST, DAST, OWASP, MITRE, proteção contra DDoS, LGPD, auditoria e SIEM.
Para que serve
Encontrar vulnerabilidades cedo, quando ainda são mais simples e baratas de corrigir.
Caso de uso
O pipeline encontra uma vulnerabilidade crítica em uma biblioteca e bloqueia a publicação daquela versão.
No ToggleMaster
O código e as aplicações serão analisados automaticamente antes da implantação. Uma falha grave deve interromper a esteira.
04

Segurança na Cloud - proteger ambiente, acessos e dados

Usaremos no projeto
Em miúdos
A AWS protege o prédio e os equipamentos da nuvem; nós ainda precisamos trancar as portas certas, controlar as chaves e proteger os dados.
Termos principais
Responsabilidade compartilhada, Zero Trust, IAM, MFA, criptografia, CSPM, CWPP e CASB.
Para que serve
Garantir que somente pessoas e sistemas autorizados acessem os recursos necessários.
Caso de uso
O pipeline recebe apenas a permissão necessária para publicar uma imagem, sem acesso administrativo a toda a conta AWS.
No ToggleMaster
Usaremos permissões mínimas, autenticação forte, criptografia e registros de auditoria para proteger a infraestrutura e os dados.

Como os pilares trabalham juntos

Um exemplo completo de uma alteração no microsserviço de autenticação.

  1. O desenvolvedor altera o códigoA mudança é enviada ao GitHub e passa a ter histórico e revisão.
  2. O GitHub Actions inicia o pipelineTestes e verificações independentes podem rodar em paralelo.
  3. O DevSecOps verifica a mudançaSAST analisa o código; outras verificações procuram dependências e configurações vulneráveis.
  4. A entrega é bloqueada se houver risco graveUma vulnerabilidade crítica impede que a versão avance para produção.
  5. A nova versão é preparadaO pipeline cria a imagem do serviço e registra qual versão foi produzida.
  6. O Kubernetes recebe a versão aprovadaA implantação acontece apenas depois dos controles anteriores.
  7. A infraestrutura continua reproduzívelRede, cluster e serviços da AWS permanecem descritos e controlados pelo Terraform.
  8. IAM, criptografia e logs protegem a operaçãoAcessos são limitados, dados são protegidos e atividades podem ser auditadas.
