CI/CD

Da primeira esteira automática até GitOps, Terraform, serverless e AIOps - em 7 aulas, com siglas explicadas e aplicação prática no ToggleMaster.

Guia de estudo 7 aulas + glossário de siglas + pipeline do Tech Challenge Atualizado em 2026-07-18

O que é CI/CD?

É uma linha de montagem do software. Cada mudança percorre automaticamente estações de build, teste, segurança e entrega. Se uma estação encontra um problema, a versão para antes de chegar ao usuário.

Por que combina com o nosso projeto

O ToggleMaster tem cinco microsserviços. Repetir manualmente testes, imagens e implantações para todos eles seria lento. Com pipelines reutilizáveis, seguimos o mesmo padrão de qualidade para cada serviço e sabemos exatamente qual versão está no EKS.

As 7 aulas, uma a uma

Cada ficha explica o conteúdo, sua utilidade, um caso real e como ele se encaixa no Tech Challenge.

01

Fundamentos e Arquitetura de Pipelines de CI/CD

Essencial no projeto
Em miúdos
Apresenta a linha de montagem: cada mudança passa por build, testes e entrega. Também mostra a diferença entre deixar uma versão pronta e publicá-la automaticamente.
Siglas e termos
CI, Continuous Delivery, Continuous Deployment, DevOps, Pipeline as Code, workflow, job, step, action, Jenkins, GitHub Actions, Shift Left, SAST, SCA e DAST.
Para que serve
Padronizar a entrega, reduzir erros manuais e descobrir bugs ou vulnerabilidades mais cedo.
Caso de uso
Uma pull request inicia build e testes. Se um teste falha, o pipeline bloqueia a união daquela mudança.
No ToggleMaster
O GitHub Actions será a ferramenta principal para validar cada microsserviço antes de produzir uma nova imagem.
02

Otimização e Escalabilidade de Pipelines

Muito útil no projeto
Em miúdos
Depois que a esteira funciona, aprendemos a dividi-la em estações claras, executar tarefas ao mesmo tempo e reaproveitar a mesma receita em vários projetos.
Siglas e termos
Multi-stage, dependência com needs, paralelismo, matrix strategy, include, exclude, fail-fast e workflows reutilizáveis.
Para que serve
Diminuir o tempo de espera, facilitar diagnósticos e garantir um padrão comum em escala.
Caso de uso
Testar várias versões de uma linguagem em paralelo ou executar os testes dos cinco serviços simultaneamente.
No ToggleMaster
Podemos criar workflows reutilizáveis de teste, análise e publicação, chamados pelas pipelines de `auth`, `flag`, `targeting`, `evaluation` e `analytics`.
03

Entrega Contínua para Kubernetes

Essencial no projeto
Em miúdos
Ensina o caminho entre o código aprovado e o Kubernetes: construir a imagem, enviá-la ao registro e atualizar a aplicação com menor risco.
Siglas e termos
build → push → deploy, imagem, registry, manifesto YAML, Helm, Kustomize, Blue/Green, Canary, GitOps, ArgoCD e FluxCD.
Para que serve
Automatizar a entrega de containers e controlar como uma nova versão substitui a anterior.
Caso de uso
Liberar uma nova versão para uma pequena parcela do tráfego e ampliar somente depois que ela demonstrar estabilidade.
No ToggleMaster
A pipeline produzirá uma imagem identificada pela versão do código e a implantação final ocorrerá no cluster EKS.
04

Adoção de GitOps com ArgoCD e FluxCD

Essencial no projeto
Em miúdos
O Git passa a guardar a “foto oficial” de como o ambiente deve estar. Um operador compara essa foto com o Kubernetes e corrige diferenças.
Siglas e termos
GitOps, estado desejado, reconciliação, fonte única da verdade, push-based, pull-based, ArgoCD, FluxCD e entrega progressiva.
Para que serve
Aumentar rastreabilidade, consistência e segurança, evitando dar ao pipeline acesso administrativo direto ao cluster.
Caso de uso
Alguém altera manualmente uma configuração no Kubernetes. O ArgoCD detecta o desvio e restaura o estado registrado no Git.
No ToggleMaster
Usaremos ArgoCD: o pipeline atualiza no Git a tag da imagem aprovada, e o ArgoCD puxa essa mudança e sincroniza o EKS.
05

IaC em Pipelines com Terraform

Essencial no projeto
Em miúdos
A infraestrutura também ganha sua linha de montagem. Antes de modificar a AWS, o Terraform mostra um orçamento detalhado do que pretende criar, alterar ou destruir.
Siglas e termos
IaC, HCL, terraform init, terraform plan, terraform apply, plan salvo, state remoto, módulo, workspace, BSL e OpenTofu.
Para que serve
Revisar e automatizar mudanças de infraestrutura com histórico, aprovação e estado compartilhado.
Caso de uso
Uma pull request mostra o plan. Somente depois da revisão a alteração autorizada é aplicada na AWS.
No ToggleMaster
A VPC, o EKS, os bancos e os serviços gerenciados serão criados pelo Terraform; o estado deverá permanecer remoto e protegido.
06

CI/CD para Arquiteturas Serverless

Conhecimento complementar
Em miúdos
Em serverless, o provedor cuida dos servidores e o pipeline concentra-se em empacotar funções e declarar os recursos necessários.
Siglas e termos
Serverless, FaaS, AWS Lambda, AWS SAM, CloudFormation, sam build, sam deploy, staging, production e OIDC.
Para que serve
Entregar funções sob demanda com rastreabilidade, credenciais temporárias e cobrança ligada ao uso.
Caso de uso
Uma função Lambda processa um evento apenas quando ele ocorre, sem manter um servidor ligado continuamente.
No ToggleMaster
Serverless não é o centro da arquitetura baseada em EKS. Porém, o uso de OIDC para o GitHub Actions acessar a AWS com credenciais temporárias é muito útil para o projeto.
07

AIOps e Automação em Pipelines de CI/CD

Evolução futura
Em miúdos
A esteira começa a aprender com logs e falhas anteriores para priorizar testes, reduzir alertas inúteis e sugerir ou iniciar correções.
Siglas e termos
AIOps, inteligência artificial, aprendizado de máquina, análise preditiva, fadiga de alertas, resposta a incidentes, rollback e self-healing.
Para que serve
Sair de uma operação apenas reativa e antecipar problemas com base em padrões.
Caso de uso
A plataforma identifica que determinada combinação costuma falhar, prioriza os testes relevantes e alerta antes do deploy.
No ToggleMaster
É uma melhoria desejável, não o primeiro passo. Podemos demonstrar alertas e rollback automático; previsões por IA exigiriam histórico e dados suficientes.

Pipeline recomendado para o Tech Challenge

Exemplo de como conectar os principais conceitos das aulas ao fluxo de entrega do ToggleMaster.

  1. Pull request criadaO GitHub Actions inicia a Integração Contínua para o microsserviço alterado.
  2. Build, testes e qualidadeJobs separados validam se o código compila e se o comportamento esperado continua funcionando.
  3. Verificações de segurançaO pipeline analisa código, dependências e imagem. Risco crítico bloqueia a entrega.
  4. Imagem versionadaA imagem aprovada recebe uma tag ligada ao commit e é enviada ao ECR.
  5. GitOps registra o estado desejadoA tag da imagem é atualizada no repositório ou diretório de manifestos.
  6. ArgoCD reconcilia o ambienteO operador detecta a mudança no Git e sincroniza o cluster EKS.
  7. Observação e recuperaçãoHealth checks, logs e alertas ajudam a confirmar a versão; se necessário, ocorre rollback.
Pipeline de aplicação e pipeline de infraestrutura são diferentes A aplicação muda com mais frequência e segue o fluxo de imagens e GitOps. O Terraform deve ter uma esteira própria, com plan revisado antes do apply.
